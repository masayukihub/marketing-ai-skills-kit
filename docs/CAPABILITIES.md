# 能力与保留边界

本版是通用化重构，不是原私人环境的逐文件复制。旧系统的跨仓库 Renderer、付费服务、登录状态和公司数据不随发行包提供。

| 保留的方法 | 可执行部分 | 仍需人的部分 |
| --- | --- | --- |
| Product Truth / Claim 分层 | 来源、字段、状态、有效期检查 | 证据真实性、正式审批 |
| 项目恢复 | 最小上下文、来源 Hash、Handoff | 决策与正式 Memory 写回 |
| VOC | 去重、评分、透明关键词主题 | 原文语义、用户洞察、市场代表性 |
| 页面故事 | 分区、范围覆盖、同品牌限制、HTML | 文案策略、产品图、语义一致性 |
| Campaign | 加权指标、口径冲突检查 | 归因解释、预算与执行决策 |
| KOL | 条件筛选、样本播放中位数 | 受众匹配、报价、披露、合作判断 |
| EDM | 单封/系列 HTML、共用模块影响、继承记录、版本化审核和评论计划 | 来源语义、整篇视觉、共享网站、ESP/邮件客户端 QA、法务、发送授权 |

没有连接或执行过的能力，不能因 Skill 提到了它就声称已运行。

## 图文一致性

HTML 同时展示准确文案、绑定主张、所需画面证据和实际图状态。
程序不会仅凭布尔字段或存在一张图片就自动给 PASS。实图需要审核者判断 product accuracy、copy match、implied claim 和 mobile proof。
图片缺失不阻塞草稿规划，但阻塞真实视觉交付。

## 升级路线

优先验证真实用户能完成一次本地输入→草稿→人工审核，再加可选连接器或图片工具。
不要为尚未实现的适配器创建“可用”空目录。每个新增适配器应有配置说明、权限边界、能力探测和失败测试。
